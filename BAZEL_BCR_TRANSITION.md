# Bazel Central Registry (BCR) Transition Plan

This document tracks the plan and status for upstreaming our custom local Bazel registry modules to the official [Bazel Central Registry (BCR)](https://github.com/bazelbuild/bazel-central-registry).

Upstreaming these modules is tracked under **Bug 528316110**.

---

## 1. Overview

To support Bzlmod in the Android Emulator (`aemu`) workspace, we created a local Bazel registry (`build/bazel/registry`) containing several third-party modules that were either missing from the BCR or required custom patches.

To reduce our maintenance overhead, we plan to transition these modules to the official BCR. Once upstreamed, we can remove them from our local registry and resolve them directly from the internet.

---

## 3. Temporary Hosting (Internal GCS Mirror)

For our local registry, the source archives for these modules are temporarily hosted in our internal Google Cloud Storage bucket:
*   **Bucket**: `gs://emu-next-bazel`
*   **Path Structure**: `gs://emu-next-bazel/registry/[module_name]/[archive_file]`
*   **HTTP Mirror URL**: `https://storage.googleapis.com/emu-next-bazel/registry/...`

These URLs are defined in the `source.json` files inside our local registry (e.g. `build/bazel/registry/modules/libyuv/1948/source.json`).

---

## 4. Transition Process to BCR

The official BCR requires source archives to be hosted on stable, public, and permanent URLs (typically official GitHub releases). The BCR team will not accept PRs pointing to internal or temporary buckets.

### Step-by-Step Transition Steps:

1.  **Establish Stable Public Source URLs**:
    *   For all dependencies, identify the official release tarball URL from the upstream project (e.g. GitHub Releases, VideoLAN GitLab releases).
    *   If we must use a specific git snapshot (like we did for `dav1d` and `libyuv`), we must ensure the archive URL generated by the hosting provider (GitHub/GitLab) is stable and permanent.
    *   If BCR requires it, the archives may be mirrored to a BCR-managed bucket.

2.  **Submit PR to BCR**:
    *   Fork the [bazel-central-registry](https://github.com/bazelbuild/bazel-central-registry) repository.
    *   Create a new module directory under `modules/` for the target library.
    *   Create `metadata.json` (declaring metadata, homepage, and versions).
    *   Create a version subdirectory (e.g. `modules/libyuv/1948/`):
        *   `source.json`: Point to the stable public URL and define the integrity hash (SHA-256).
        *   `MODULE.bazel`: Declare the module and its Bzlmod dependencies.
        *   `patches/` and `presubmit.yml` (if needed for testing).
    *   Submit a Pull Request to the upstream BCR repository.

3.  **Community Review & Verification**:
    *   The BCR team runs automated presubmit checks (building the module on Linux, macOS, and Windows).
    *   Address any feedback or build failures reported by the BCR bots.

4.  **Local Registry Cleanup**:
    *   Once the PR is merged into the official BCR, remove the module directory from our local registry (`build/bazel/registry/modules/[module_name]`).
    *   Update the version in the root `MODULE.bazel` to point to the newly released BCR version (if different).
    *   Bzlmod will now fetch the module automatically from the internet.
